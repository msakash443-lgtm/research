# Data model

This document describes the live SQLAlchemy model in [`backend/app/models.py`](../backend/app/models.py). It is an implementation reference, not a second schema definition. Migrations in [`backend/migrations/versions/`](../backend/migrations/versions/) are the deployment history; PostgreSQL is the only supported application database.

## Conventions

- All `Timestamped` models inherit `created_at` and `updated_at`. Models that inherit only `Base` declare their timestamps explicitly when needed.
- UUID primary keys are generated by the application unless noted otherwise. `ConnectorBreakerState.name` is the only non-UUID primary key.
- `JSON` stores structured values whose shape is validated by the owning service/schema. JSON does not imply that source text, prompts, or model answers may be placed in audit payloads.
- `project_id` scopes project data. Some historical/audit tables intentionally keep a plain project id so their records survive project deletion or user erasure.
- Append-only records are protected by ORM listeners and/or database triggers. A correction is represented by a new row or event, not by rewriting history.
- `created_by`, `actor`, `decider`, and similar fields are audit identities stored as strings; they may identify a user or an agent and are not universally foreign keys.

## Integrity rules implemented around the model

- `audit_events`, `screening_decisions`, `screening_discussion_notes`, `seed_check_runs`, `source_excerpts`, note revisions, AI suggestion events, document versions, figure versions/checks, authorship events, similarity checks, provenance reports, section approvals, interpretation findings/reviews, and other ledger records are append-only where documented above.
- `SourceExcerpt.content_hash` and evidence/claim checks prevent unverifiable quotations from becoming confirmed support.
- Composite foreign keys on theory/construct, conceptual paths, research questions/objectives, and hypotheses prevent cross-project links.
- Gate approval is separate from task execution. No model row or task status can authorize a gate on behalf of a human.
- AI provenance is stored on AI-bearing records (`model_id`, `prompt_version`, producer/actor fields). Participant excerpts are a distinct model path and must use the configured local endpoint.
- Retrieved source text is data, not instructions. Fencing and prompt policy live in the application services, not in this schema document.
